# 相場ボード 設計書（MotoExport Pro 強化）

作成日：2026-07-11
母体：`motorcycle-export-dashboard`（Next.js 16 / Supabase / cheerio / Vercel）

---

## 1. 目的・背景

BDS/JBAのオークションは効率市場で鞘が薄い。現状渡しのコモディティ（アドレス/カブ）は粗利¥5〜12kで、目標¥20kに構造的に届かない。過去の高掴み（PCX・大ジャイロ ¥172,590→赤字）も相場感の欠如が原因。

**このボードが解決すること：**
1. **実売裏付け** — aucfanの実際の落札データで相場を固める（勘・推測をやめる）
2. **完全手数料** — 落札料・消費税・名義代・輸送費・ヤフオク手数料・広告費・整備コストを全部引いた「本当の上限落札額」を出す
3. **整備で¥20kを作る** — 軽整備の付加価値で、オークションに無い鞘を作る
4. **ゼロメンテ** — ふっちーが一切触らなくても自動更新。古くなったら自分で警告（fail-loud）

**位置づけ：** ボードはオークション仕入れを「赤字を踏まない・薄利と分かって買う」規律化ツール。太い鞘は市場外ルート（田和/グロム型）で取る。ボードは毎日それを可視化してルート開拓を促す。

---

## 2. アーキテクチャ（3コンポーネント）

### ① データパイプライン（更新エンジン）
- **aucfanプレミアム**をスクレイプ（Playwright自律 or cheerio）→ 各車種の落札実績（直近90日）
- 取得：**実売の分布**（中央値・下位30%・安値〜高値・n数）
- **1円スタート実売に絞る**（ふっちーの売り方と同条件の着地データ＝リアル）
- **整備済み/保証 出品 vs 現状/ノークレーム 出品の価格差＝整備プレミアム**を車種別に実測
- 保存：Supabase相場DB
- 実行：**Vercel cron で自動**（毎日 or 開催前夜）。手動更新はゼロ

### ② 相場計算エンジン
車種ごとに「会場別・上限落札額」を逆算（完全手数料モデル＋弱気売値＋整備後売値）。3ゾーン判定を返す。

### ③ 会場ビュー（スマホ）
Next.jsのモバイル画面。型式/車名で即検索 → 会場別上限・判定色・分布レンジを1画面。

## 3. 完全手数料モデル

### 仕入側
| 項目 | 値 |
|---|---|
| 落札額 | 変数（求める対象） |
| 落札料（BDS・B会員） | 下記ブラケット（公式料金表・税別・**買主は落札料のみ**。出品料/成約料は売主側） |
| 落札料（JBA） | 5万未満¥4,400／20万未満¥6,600／50万未満¥8,800 |

**BDS落札料（B会員・税別）※7/3計算書と検算一致**
| 落札金額 | 落札料 | 落札金額 | 落札料 |
|---|---|---|---|
| 5万未満 | ¥4,200 | 50万未満 | ¥8,800 |
| 10万未満 | ¥5,500 | 60万未満 | ¥9,600 |
| 20万未満 | ¥6,900 | 80万未満 | ¥10,200 |
| 30万未満 | ¥7,400 | 100万未満 | ¥11,200 |
| 40万未満 | ¥8,200 | 100万以上 | ¥12,200 |

※つど払い（名変代行・書類等）は使った時のみ発生。既定¥0、発生時のみ加算。
| 消費税 | 10%（車両代＋落札料に対して） |
| 名義代（幸新） | **月¥3,000固定**（会員資格借用の月額）。per-台＝¥3,000÷月間落札台数で配賦→台数増で希薄化（例：40台なら¥75/台）。上限計算では「月間見込み台数」で割った小額を引く |
| 輸送費 | **会場別**。既定：BDS堺≈¥1,000／JBA神戸≈¥1,500（台数で逓減）。**関西以外は都度「要確認」**（下記・会場マスタ） |

### 売却側
| 項目 | 値 |
|---|---|
| ヤフオク手数料 | ¥1,980（固定） |
| 広告費 | ¥700（ON/OFF可・既定ON。1円スタートは着地上がるので実質ペイ） |
| 整備コスト | 工賃（時間×¥1,500）＋部品代（軽整備標準） |

### 逆算式
```
上限落札額 =
  ( 整備後・弱気売値 − 目標粗利 − 名義3,300 − 輸送費 − 整備コスト − ヤフオク1,980 − 広告700 )
  ÷ 1.1
  − 落札料(落札額の帯)
```
※落札料が落札額に依存するため軽く循環 → エンジンが帯を自動で当てて解く。

### 会場マスタ（送料は会場別・非関西は要確認）
| 会場 | 地域 | 送料（既定） | 状態 |
|---|---|---|---|
| BDS 関西（堺） | 大阪 | ¥1,000 | 本拠・既定 |
| JBA 神戸 | 兵庫 | ¥1,500 | 自社トラックでバッチ回収可 |
| BDS 関東 | 千葉 | ≈¥10,000（≤125cc陸送） | 遠隔・太い玉専用 |
| BDS 九州 | 福岡 | ≈¥13,000（≤125cc陸送） | 最遠・太い玉専用 |
| JBA 神奈川 | 関東 | ≈¥10,000（≤125cc陸送） | 遠隔・太い玉専用 |

**送料＝会場（距離）× 車体区分 のルックアップ表**（数字は埋めながら育てる）
- 距離：堺¥1,000 ＜ 神戸¥1,500 ＜ 関東/神奈川¥10,000 ＜ 九州¥13,000（≤125cc標準原付）
- **車体区分の割増**：ジャイロ等バルキー車（3輪・かさ張る）は割増、>125ccも割増。同一会場でも車体で送料が変わる
- 未設定の（会場×車体）は「送料要確認」赤フラグ＝fail-loud
- 遠隔で買うのは**その送料を飲んで尚¥20k乗る玉だけ**。遠隔ジャイロは送料過大でほぼ🔴（ボードが会場別上限で自動判定）
- 送料未設定・未知の会場は「送料要確認」赤フラグ。会場は今後増える前提、マスタに1行追加で対応（ゼロメンテ）

## 4. 判定ロジック

### 売値の扱い（＝一番の肝）
売値は当てにいかない。**安全側で引く**。
- **弱気売値＝実売分布の下位30%ライン**を基準に上限を計算（1円着地が下振れても粗利フロア確保）
- **整備後売値**＝弱気売値 ＋ 整備プレミアム（aucfan実測。軽整備で乗る分だけ）
- 画面に**分布レンジ（安値〜中央〜高値・n数）**も併記 → 現車が上玉ならふっちーの目で上限を上げられる
- **状態＝BDS評価点で一次補正 → ふっちーの目で最終補正**（下記）

### BDS評価点（検査評価基準）による状態補正 ★状態ブレ対策の核
BDSは車両を**評価点1〜10**でグレーディング（2025年版 検査評価基準表・SIBO）。これを状態シグナルに使い、「状態でブレる」問題をデータで半分潰す。

| 評価点 | 状態イメージ | 影響 |
|---|---|---|
| 8-10 | 未使用〜フルノーマル無事故・無転倒 | 売値↑ |
| 6-7 | 小錆・小傷・消耗品交換必要・修復歴無 | 売値≈中央・軽整備で商品化 |
| 4-5 | 中錆・中傷・微〜小改造・要整備（修復歴有含） | 売値↓・整備↑ |
| 2-3 | 大錆・大傷・修復歴・分解整備必要 | 売値↓↓・整備大 |
| 1 | 現状ノークレーム・商品化不可（蚤の市） | 手出し注意 |

**評価点は二役：**
1. **売値補正** … 中央値 × 評価点係数（高評価＝上振れ／低評価＝下振れ）
2. **整備コスト見積** … 低評価＝消耗品交換必要 → 整備費を自動で厚めに見積

**補正カーブの作り方：** aucfan落札データに評価点が付いていれば「評価点↔落札額」を実測して係数を自動生成（ゼロメンテ）。無ければ既定カーブ（例：6点=1.0基準、±1点ごとに±5〜8%目安）を初期値にし、実績で補正。

会場フロー：現車のBDS評価点を入力 → 補正済み売値・補正済み整備コスト → 上限落札額。

### 3ゾーン
| ゾーン | 定義 | 意味 |
|---|---|---|
| 🟢 本命 | 上限落札で粗利¥20,000以上 | 出たら即押さえる（稀） |
| 🟡 回転 | 粗利が「回転フロア」〜¥20,000 | 買えるが薄い。玉が回るなら可 |
| 🔴 赤字 | 粗利が回転フロア未満（breakeven超） | 絶対に買わない（PCX/大ジャイロ事故の防止） |

### 回転フロア＝仕入値 × 15%（ROIハードル）
- 手入力ゼロで「車種で自動的に変わる」を実現（ゼロメンテ原則）
- 安い車は薄利でも回す／高い車は資本相応の太い粗利を要求
- 例：アドレス¥60k→フロア¥9k／カブC90 ¥128k→¥19k／モンキー125 ¥225k→¥34k
- ※15%は調整可（堅め20%／回転優先12%）

### 下振れ注意フラグ
1円着地が下位30%まで落ちると赤字になる玉は🟡でも警告表示。

## 5. ゼロメンテ + fail-loud

「ふっちーは絶対メンテしない」を設計条件にする。
- **更新は全自動**（Vercel cron）。手動リフレッシュは廃止
- 会場ビューに常時**「最終更新：○日前」**を大きく表示
- **○日以上古い → 画面が赤で「相場データ停止中・入札するな」**
- スクレイプ破損・aucfanログイン切れ → **LINE通知で催促**、その間ボードは赤表示
- **送料未設定の会場は「送料要確認」赤フラグ** → 送料を入れるまで上限を出さない（関西以外で誤った送料前提で買う事故を防ぐ）
- 放置しても事故らない（古い時は必ず「古い」と分かる）

## 6. データモデル（Supabase 想定）

- **車種マスタ**：車名/型式/クラス/aucfan検索キー/⚠高掴み注意フラグ
- **相場スナップショット**：車種×取得日／中央値・下位30%・安値・高値・n数／1円スタート絞り込み値
- **整備プレミアム**：車種×（整備済み売値中央 − 現状売値中央）
- **手数料設定**：会場別 落札料ブラケット・輸送費・名義代・ヤフオク手数料・広告費・工賃単価・整備標準
- **スクレイプ稼働ログ**：最終成功日時・失敗フラグ（fail-loud用）

---

## 7. 会場ビュー（スマホ）要件

- 型式/車名で即検索（v5の速さ維持）
- 1車種タップ → 実勢中央・下位30%・n数・**会場別上限（BDS/JBA 2本）**・判定色
- ⚠高掴み注意フラグ（PCX・大ジャイロ等）
- n数が少ない車種は「サンプル薄・注意」表示（裏付けの弱さを隠さない）
- 整備あり/なしの上限を切替表示（整備で¥20k届く車が分かる）
- 最終更新日・データ鮮度の赤警告
